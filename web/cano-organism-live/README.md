# CANO Live Organism Observatory — public simulation monitor

This page renders only public, synthetic, reproducible organism simulation records from the isolated GitHub state branch. It performs independent browser SHA-256 checks before showing any numeric state, compares the saved observations to division-disabled controls, and never creates organisms or runs a model in the browser. Refreshes the state every 90 seconds. If data cannot be verified, shows an explicit error instead of fabricated or cached metrics.

Published using a free Render static site via GitHub source branch; not the existing production Render CANO service. No keys, owner data, personal data, model APIs, public write endpoints or physical actuation.

**Source branch**: `feature/cano-live-organism-observatory-20261107`.
**State branch**: `experiment/cano-digital-state-20261107`.
**Real computation**: `main:.github/workflows/cano-digital-organism-calendar.yml` scheduled once daily at `05:47 UTC`; GitHub job writes to state branch when successful. The scheduled action is not proven to have executed just because this monitor is live. A public monitor does not imply an autonomously training agent, sentience, biological life or self-building robotics.

**Build on Render**: command `mkdir -p public && cp web/cano-organism-live/index.html public/index.html`, publish path `public`.

## Scheduled-run freshness (2026-11-08 hardening)
The dashboard now distinguishes *record integrity* from *on-schedule progress*. SHA-256-consistent files may be old; prior versions displayed only the cryptographic "verified" status even after the next expected daily run.

The source-of-truth simulator is scheduled for **05:47 UTC**. The live page shows the next scheduled time in Europe/Istanbul, the most recently expected UTC archive date, and a separate state:
- `current`: latest archive date is within the expected window (this **does not prove** GitHub Actions ran).
- `pending`: scheduled slot passed but the two-hour runner allowance is still open.
- `stale`: after 07:47 UTC, the expected current-day record is absent; amber main pill and red warning, even if older records pass their hashes.
- `future`: future-date data cannot be interpreted as a completed scheduled run.
- `error`: record hashes or schema cannot be verified; metrics are hidden.

Run `node web/cano-organism-live/tests/test_calendar_freshness.cjs` to test 8 boundary cases without external services, and `node web/cano-organism-live/tests/test_dashboard_vm.cjs` for valid/tampered synthetic records. The Chromium public-site smoke runs after a push to the live site source branch, not on an un-deployed PR.

No new organisms are generated by the dashboard; it still only reads synthetic public GitHub records. A passing date-window check is not independent evidence of the scheduler's run history; verify GitHub Actions event/log and archival readback for the full acceptance gate.
