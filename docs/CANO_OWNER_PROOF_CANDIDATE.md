# Transaction-bound owner proof (candidate only)

On an isolated PostgreSQL rehearsal database, an unsigned owner GUC change exposed two synthetic rows. A restrictive HMAC policy denied the same query. Eight tables and six allowed roles passed 81 signed/modified/forged read controls. No production policy or deployment is authorized by this document. The adapter mode defaults to off; required mode needs separate server-side role-specific random 32-byte keys, matching protected database key registry, and the tested verifier policy. Never use DB passwords as signing keys or commit keys. Provision via protected channels; rotate and test pooling, direct login, all writes, legacy owner keys, resolver, actual app auth and rollback before enabling. A compromised trusted app signing secret is outside this boundary. Existing database-only worker role must not receive signing keys. This PR contains adapter integration and unit tests, not a production migration or proof of end-to-end deployment.
